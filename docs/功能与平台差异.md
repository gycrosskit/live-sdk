# 功能与平台差异

当前 Maven 候选为 `0.3.0-rc.3`，修正 rc.2 提前注册公共 Kuikly View 事件导致的 `PagerNotFoundException`；Android/iOS/OHOS 共用此修复。配套沿用 ohpm HAR `0.3.0-rc.3` 和既有原生 Pod/标签，原生渠道不重发。当前仅维护 core、Kuikly raw / KuiklyCompose 与原生会话，源码、编译、远程消费和设备验收分别判断；历史发布证明保留原范围。

组件提供 Android/iOS 的腾讯 AtomicX 原生视频、预览、观看会话、账号门禁、互动和唯一快照。根工程仅聚合；`live-kuikly` 提供 raw View 与 KuiklyCompose UI，复用 `live-core`。业务账号/UserSig、品牌资料、直播间 ID、准入、业务点赞上报和页面控件由宿主提供。2026-10-22 新增 OHOS 观看源码候选，公共会话/预览/快照复用 core，原生能力经 Kuikly 与独立 HAR 接入；已分别取得固定 SHA 的 Kotlin/HAR 编译证据，最新修订须按对应 CI 回执核对；未做真机验收。

## 公开功能与合同

- Kuikly raw/Compose 均复用现有 native/core。已发布raw DSL为 `io.github.gycrosskit.livesdk.LiveVideo(init)`；`io.github.gycrosskit.livesdk.kuikly.LiveVideo(liveId, preview=false, active=true, modifier, onEvent, onController)` 会下发同房间active变化；普通重组不重复提交room，以免重开explicitRelease。移除先关事件归属再release；更换controller callback只交接句柄。
- 预览需active、visible/宿主STARTED、sessionReady等门禁均满足；COVER/LOADING/PLAYING/FAILED由真实平台回报。观看与列表预览互斥；全局队列join/leave等待和超时由core维持，不新建第二SDK会话。
- `sendBarrage`/`like`/`toggleFollow`/`refreshAudience`、快照与join/kicked/end/禁言等事件按会话代次归属。messages含sequence/timestamp/sender/content/businessId/data/kind；sequence不能单独当全局唯一ID。业务点赞上报、文案本地化和消息UI由宿主消费。
- `AndroidLiveSdkRuntime`/`IosLiveSdkRuntime`门禁不自行生成UserSig或代替真实登录。iOS需安装宿主bridge；关闭账号资格并停止预览后再清账号，共用IM身份的借用/自有规则须与客服串行协调。
- Android `AtomicXSession.isLoggedInAs` 与 iOS `GycLiveClient.isLoggedInAs` 按实际 V2TIM 用户和 AtomicX/IM 登录状态判定；异步 `loginUserInfo` 为空、迟到或旧值不参与认证。登录 completion 仍检查 SDKAppId 与操作代次，成功后独立同步 nickname/avatar；资料写入完成不属于登录成功承诺。owned logout 真正调用 SDK，borrowed/foreign/AppId 接管只清本组件状态。
- 点赞共同能力不等于相同UI入口：`like()`发起命令，已注入native reporter在SDK确认成功后报告批次数；snapshot的likeEffectSequence只服务效果触发，不能当业务上传ACK。`LiveLikeBatcher`是core内部实现，不是UI公开参数。[Android原生注入](../live-kuikly/src/androidMain/kotlin/io/github/gycrosskit/livesdk/GycLiveView.kt)、[Swift原生注入](../live-kuikly/ios/GycLiveView.swift)、[iOS Controller](../live-kuikly/src/iosMain/kotlin/io/github/gycrosskit/livesdk/IosKuiklyLiveController.kt)。
- Main同步 `stopActivePreview` 与Renderer可挂起 `stopActivePreviewAndAwait` 不可互换。不要阻塞Renderer/Main互等。
- PiP `accepted`只表示平台请求受理/实验接口提交，不表示浮窗可见；真实状态须宿主回报。iOS实验接口、AndroidActivity PiP、应用内小窗是不同接线，不能用共同snapshot当视觉证据。

iOS 互动只允许持有原生 view 且已 joined 的 session 发起。排队、结束及释放后的实例不能写当前全局 Store；点赞实际批次同样检查归属。释放时仅已 joined 的旧 owner 可在让出令牌前冲刷尾批，迟到的弹幕成功回执按失败结算。
