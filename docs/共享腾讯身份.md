# 共享腾讯身份与中立 IM 源

本轮候选为 Maven/Pod `0.2.1-rc.3`。以下是源码契约；发布、远程消费与设备会话验收另行记录。iOS 原生渠道为 CocoaPods，仓库没有 Swift Package。

## 实际身份与注销权限

AtomicX 和 AI Desk 使用进程内同一 `V2TIMManager`。组件同时核对厂商 facade 状态与实际 `V2TIMManager.getLoginUser/getLoginStatus`，不能仅依据 AtomicX `LoginStore` 或 AI Desk 的初始化标记判断 runtime 为空。Android AI Desk 的 `isUserLoggedIn` 还依赖 Desk 自己的准备标记，可能在 Live 已登录时返回 false。

从空 runtime 成功登录的组件记录注销权限；借用已有同用户的 runtime 只记录本组件准备成功，不取得注销权限。`logout/reset` 在执行厂商注销前再次核对实际用户，借用或已被 foreign 用户接管时只清本组件状态。注销失败且实际用户仍匹配时保留权限，让宿主 cleanup barrier 可以重试。SDK login pending 时拒绝新 prepare，旧回调不能覆盖新一代准备状态。

已知 AtomicX/Desk 缓存的 SDKAppID 与本组件准备身份不同时，即使 userId 相同也不取得旧注销权限，准备 RESET、mayOwn、注销和失败恢复用同一判定。已知缓存与目标不同时，借用路径拒绝触发初始化，因为厂商切换 SDKAppID 可能隐式注销全局 IM。Android `TUILogin.getSdkAppId()` 与 iOS `TDeskLogin.getSdkAppID()` 提供 Desk 配置缓存，直接用于保护已知冲突。V2TIM 没有公开的全局实际 SDKAppID 查询，因此宿主仍须给 Live/客服提供同一个已核对的腾讯 SDKAppID。相同 userId 的外部注销再登录没有公开 owner token，组件不能识别这种完全同身份替换，不能把本地记录解释为跨任意外部 SDK 调用的排他所有权。

## 宿主串行接线

继续使用宿主现有 `SdkSessionTasks`，每个组件各持自己的 Tasks/cleanup owner。给两个 Tasks 注入同一个 `executionMutex`；后台实际 SDK block 持锁直到厂商 completion，而调用方的 timeout/cancellation 只结束等待。`reset` 先等待自己的前一任务，再取得共享锁；不要持共享锁等待前一任务，也不要共享同一 Tasks 实例，否则 reset 去重会丢失另一组件 cleanup。

组件不新增共享 Session，不读取 App 账号、环境或 UserSig。Android 客服不可取消的 init/profile/unInit 在 `NonCancellable` 原生 await 中完成，之后才提交身份与释放宿主锁。Swift 适配器保持真实 SDK completion 接线。宿主的 Live callback→suspend 桥也必须保留后台操作直到 callback，不能把原生生命周期绑定到页面 Job。

## Android 原生 IM 事件

```kotlin
val imSource = AndroidLiveImSource()
imSource.connect(setOf(roomGroupId), object : LiveImObserver {
    override fun onRestCustomData(groupId: String, payload: String) { /* 交给既有 common parser */ }
    override fun onCurrentUserRemoved(groupId: String, operatorUserId: String) { /* 交给现有房间事件 */ }
    override fun onGroupDismissed(groupId: String) { /* 交给现有房间事件 */ }
    override fun onKickedOffline() { /* 交给唯一 Session owner */ }
    override fun onUserSigExpired() { /* 交给唯一 Session owner */ }
})
// 房间解绑；进程 owner 最终释放时 close。
imSource.disconnect()
imSource.close()
```

source 只注册/撤回 `V2TIMGroupListener` 与 `V2TIMSDKListener`。它过滤其他群和旧绑定的迟到事件，成员踢出依据实际 SDK 当前用户，REST custom payload 原样交给宿主。terminal callback 先使当前绑定失效并撤回监听，再向观察者发一次事件；观察者重连不会被旧回调清掉。监听撤回失败保留 handle 供 `disconnect/close` 重试。

iOS 继续使用现有 `GycLiveClient.connectLiveIm(...)/disconnectLiveIm()` 与 `GycLiveImObserver`，同样过滤旧绑定与终态重复通知。业务 payload parser、房间退出决策、账号过期恢复均由宿主既有 owner 保留。

## 定向验证

公共函数的 native SDK 调用不由纯策略测试代替。`LiveAccountOwnershipTest` 覆盖 own/borrow/foreign/SDKAppID 和异步 reset 后重新核身份；`AndroidLiveImSourceTest` 通过注册边界替身覆盖旧监听、异群、实际用户成员踢出、终态一次、部分注册和失败撤回重试。`verification/ownership/main.swift` 验证 Swift 同策略。Android 编译/单测、iOS KLIB/单测与真实厂商 Pod 最终链接的实际结果记录于开发验证文档。
