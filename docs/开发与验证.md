# Live SDK 开发与验证

从仓库根目录执行；第三方安装见 [README](../README.md)。需要 JDK、Android SDK 与 Xcode；最终 iOS Native 链接还需要真实 Kuikly Render Framework。

## 验证与归档

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
bash scripts/verify.sh
# 指定真实原厂 Render Framework 后做 Swift 类型检查和 iphoneos 最终链接
LIVE_KUIKLY_IOS_FRAMEWORK_DIR=/path/to/parent/of/OpenKuiklyIOSRender.framework bash scripts/verify-ios-native.sh
```

脚本执行受影响 Android/iOS 编译、状态机/协议测试、staging Maven 消费、Android APK/D8、依赖无 Compose 检查与同时消费 CMP/Kuikly 的单 SDK 检查。[验证记录](验证记录.md)区分源码、编译、产物消费、最终链接和设备验收。

`archive-prebuilt.sh` 为 macOS 生成 Maven 归档，腾讯 SDK 仍使用原厂依赖；JitPack 在发布后校验 `release-checksums.txt` 中 immutable tag 的归档哈希，不在 Linux 临时编译 UIKit KLIB。预发布归档的校验值记录在 `release-checksums.txt`；当前预发行远程消费使用 `-PremoteOnly -PliveVersion=0.2.1-rc.5`，该模式仅从 JitPack 读取本组件，排除 staging 与 mavenLocal。Release 与 JitPack 制品审计已通过，独立消费者结果见 [rc.5 验收记录](0.2.1-rc.5远程发布验收.md)。


## 验收范围

构建、协议/状态机测试、发布产物消费与真实账号/设备业务验收分别记录。源码和独立远程消费已覆盖 Android APK/D8、iOS KLIB/Framework 与原生链接，设备画面、声音、进房、后台恢复仍需接入应用验收。rc.10 候选的 live-core 新增 OHOS 中立协议 KLIB；root/CMP/Kuikly 播放仍只面向 Android/iOS，没有 OHOS AtomicX/runtime 或 HAR，不承诺鸿蒙播放验收。

线程边界改动使用 `:live-core:testDebugUnitTest :live-core:iosSimulatorArm64Test :live-core:compileKotlinIosArm64` 定向验证。`AtomicLivePreviewControllerTest` 用独立 Main 调度器检查后台停止保持挂起、detach 完成后才放行下一 SDK 操作；`AtomicAudienceSessionTest` 检查退出后的入房成功不更新房间、仍离房清理，终态迟到事件不再次离房。调度器测试验证顺序契约，不能代替 Android Looper/UIKit 或真实腾讯账号设备验收。

2026-10-05 源码回归以 `--offline --max-workers=1 --no-parallel` 完成上述三项：Android XML 38 项、iOS Simulator XML 35 项，失败、错误、跳过均为 0，iOS arm64 编译成功。发布、独立远程消费与宿主接入结果分别记录在 [rc.5 验收记录](0.2.1-rc.5远程发布验收.md)。

## 独立 iOS 原生验证

Kuikly 协议测试的独立 Native runner 需要链接真实 `OpenKuiklyIOSRender`，否则会缺少
`com_tencent_kuikly_IsCurrentOnContextThread`。使用 arm64 **Simulator** 的静态 Framework，不能拿 iphoneos 产物替代；
SDK 最低 iOS 15，运行测试的 Simulator 也须满足此要求。静态库无需 rpath 或嵌入：

```bash
LIVE_KUIKLY_IOS_SIMULATOR_FRAMEWORK_DIR=/path/to/simulator/framework/parent \
  bash gradlew :live-kuikly:iosSimulatorArm64Test \
  --init-script verification/real-render-tests.init.gradle --max-workers=1 --no-parallel
```

本轮在真实 Render Framework 与 Simulator 上运行两项协议测试通过；它们验证 JSON/状态契约，
不表示页面渲染、腾讯 SDK 业务或设备生命周期已验收。

```bash
bash scripts/verify-live-native-ios.sh
```

脚本在忽略的 `build/native-live-consumer` 生成纯 UIKit 工程，使用 CocoaPods 源码消费 `GycLiveNative` 并构建 `iphoneos arm64` App。消费源实现全部原生 callback/observer 并引用公开 API，最终链接实际 AtomicX/RoomEngine/IM 符号；不依赖 Shared、KMP、CMP 或 Kuikly。生成工程及缓存不进入 Git，厂商二进制不进入归档。独立 native Pod 链接不能替代应用 Shared 薄桥编译或设备会话验收。

`0.2.1-rc.1` 已发布 Git Pod 标签及源码 Release。上面的脚本是本地 path 验证；远程验收使用独立目录的消费工程，把 Podfile 的依赖改为 [接入指南](接入指南.md#ios-原生-cocoapod) 的 Git/tag 坐标后执行 `pod install` 和同样的 `iphoneos arm64` 最终链接。对比安装源码与标签内容，核验 tag 对应提交；CocoaPods 的 tag 来源 lock 不包含 `:commit` 字段，不能声称 lock 已打印提交。真实远程结果见 [验证记录](验证记录.md#021-rc1-原生-git-pod-远程结果)。Maven 仍使用 `0.2.0-rc.2`，不改变其 metadata 或校验值。

## rc.10 表情协议与 OHOS core

`LiveEmojiProtocol` 从同一份 commonMain 目录编码/解码，保持 62 项旧客户端兼容映射、目录顺序、组合字符最长匹配和未知原文；不迁 UI 编辑、图片或 SDK 行为。core 没有平台 expect 声明，OHOS 变体仅编译共用类型/协议，不提供原生直播实现。

Kotlin 与 Compose compiler 使用现有 CrossKit OHOS fork `2.2.21-1.0.0`，core/test 协程使用 `1.10.2-1.0.0`；Android dispatcher 保持官方 `1.10.2`。Eazytec 仓库只解析 `-1.0.0` 版本，其余依赖继续使用原有仓库。新增平台需同时回归 Android/iOS，不能只检查 OHOS 编译。

```bash
bash gradlew :live-core:testDebugUnitTest :live-core:iosSimulatorArm64Test :live-core:compileKotlinOhosArm64 --max-workers=1 --no-parallel
VERSION=0.2.1-rc.10 bash scripts/archive-prebuilt.sh
# 本地 staging 验证发布边界；正式远程验收另加 -PremoteOnly --refresh-dependencies。
bash gradlew -p verification/consumer -PliveVersion=0.2.1-rc.10 -PverifyEmoji assembleDebug verifyNoCompose verifySingleSdk compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinIosX64 --max-workers=1
bash gradlew -p verification/consumer -PliveVersion=0.2.1-rc.10 -PverifyEmoji -PverifyCmp assembleDebug verifyNoKuikly verifySingleSdk compileKotlinIosArm64 compileKotlinIosSimulatorArm64 compileKotlinIosX64 --max-workers=1
bash gradlew -p verification/consumer -PliveVersion=0.2.1-rc.10 -PverifyOhos compileKotlinOhosArm64 --max-workers=1
```

归档与公开 Maven 检查须包含 `live-core-ohosarm64` 与 `ohos_arm64`，root/core/Kuikly 固定同一 Maven 版本；没有新增 root/Kuikly OHOS publication。PR 的既有远程 rc.7 基线以 `VERIFY_OHOS=0` 检查历史归档，正式候选/Release 默认检查新 OHOS 变体。Git Pod rc.7 未修改，不由 core KLIB 推断原生 SDK 或设备验收。

2026-10-07 本地候选准备：上述 fork 工具链下 core Android 47 项、iOS Simulator 43 项和 Kuikly Android 5 项测试全部通过（0 失败/错误/跳过），包含 5 项表情契约与原有快照生命周期回归。root/core/Kuikly 的 Android Release、iOS arm64/x64/Simulator arm64 编译和 core OHOS 编译通过；16 个 publication 的归档及解包复验通过，文件/sidecar 四类哈希、POM license、内部版本和平台跳转均有效。独立 staging 消费者的 Kuikly/CMP APK/D8、依赖隔离和 iOS 三架构编译通过，CMP Simulator Framework 链接通过；Kuikly staging AAR 的布局/生命周期两项契约通过，OHOS 消费者从 core KLIB 编译公开目录与 encode/decode 通过。此记录只证明本地候选准备；提交后的归档冻结、远程 Release/JitPack 消费与宿主/设备验收另行记录，原生 Pod rc.7 未改。

### rc.10 公网消费与 CI DNS 边界

rc.10 由 [PR #24](https://github.com/gycrosskit/live-sdk/pull/24) 普通合并发布；源码提交 `98179d13200e2c2eab162467a72383ad30eded39` 后重新生成归档，冻结提交 `bb534dedb9f5aa4f253d6f75bdaad639f7574eb7` 仅补 checksum，Tag 指向 `3059cc6cecc0216940ffad7b3ee162ac31510ebe`。Release 上传 digest、重新下载文件和冻结 SHA256 均为 `9a4104362d7daab496a156ae532796dae95ddd2a051668707489ff9c7548b7b3`。JitPack 真实状态为 public / ok / isTag，16 个 publication 与该提交对应；公开变体文件的四种声明哈希、MD5/SHA1 sidecar、POM license 和跳转关系通过。公开 SHA256/SHA512 sidecar 有 96 项 HTTP 404，记录为渠道缺失，不能称其已验证。

独立公网消费者仅从 JitPack 解析 rc.10（`-PremoteOnly --refresh-dependencies`），Kuikly/CMP 的新表情 API、Android APK/D8、依赖隔离、iOS 三架构编译均通过，CMP Simulator Framework 链接通过；rc.10 真实 Kuikly AAR 的 FRAME 布局与 STARTED 生命周期两项测试通过。OHOS core 消费者实际编译目录、`LiveEmojiValue` 与 encode/decode 通过。上述结果不等于 SDK 网络、设备或 OHOS 直播 runtime 验收。

[正式 Release run 37561591959](https://github.com/gycrosskit/live-sdk/actions/runs/37561591959) 的 attempt 1：Native 在公共 `.module` sidecar 读取时超时，未执行消费者；Android 在 FRAME 测试依赖解析时请求 Eazytec `kotlin-test-junit/2.2.21-1.0.0` POM 出现 `UnknownHostException: Temporary failure in name resolution`，测试未执行。保留原始失败后仅重跑失败 job 一次；attempt 2 的 Android 在 consumer plugin marker 解析失败。该次日志未提供 Eazytec 实际 HTTP/DNS 原因，不能将其推定为同一 DNS 故障。

[冷解析诊断 run 37562692386](https://github.com/gycrosskit/live-sdk/actions/runs/37562692386) 使用同一 Ubuntu runner、consumer、init 和 Java security 配置，在空 Gradle home 实际 GET KMP/Compose marker 与实现依赖，`help --debug` 1m53 成功；五个公共 POM curl 均 HTTP 200，DNS 用时 12.49–13.41 秒。第二次 marker 故障未复现，仓库过滤与 marker 存在性已确认。临时诊断 workflow 仅留在诊断分支，不作为 Release 回归结果。

CI init 复用已验证组件的每 JVM 有界 DNS 预解析：最多三次，失败仅记录并继续真实 Gradle 解析；正缓存覆盖最长 60 分钟 CI job，负缓存为 0。每个 `--no-daemon` 命令的新 JVM 独立预解析，前一消费者成功不代表后一进程已有 DNS 缓存。该修复只处理已确认的域名解析失败，不更改仓库过滤、版本、rc.10 Tag 或归档；最终 Release 验收仍要求在新 main 上明确指定 rc.10 的两个完整公网消费 job 实际成功。


CI 只在临时 `github-hosted` runner 中通过单用途 `ci-pin-fork-host.sh` 复用本 job 已验证的公网 IPv4：原 HTTPS 域名、强制 IPv4、该域名 noproxy、不跟随 redirect，只接受 HTTP 200 及 stdlib `ipaddress` 验证的公网地址，尝试写入临时 runner 的 `/etc/hosts`。后续 JVM 继续原域名与完整 TLS 校验，不固定永久 IP、不改生产仓库；探测或写入失败继续真实 Gradle 门禁，不宣称 pin 成功。

PR #25 的 `4a59af0` Native runner 启动时三次 curl 均 `exit 6`，随后 JVM 三次 UnknownHost，未能 pin。因此仅系统 curl 域名解析失败后，允许一次 [Cloudflare 官方 DoH JSON A 查询](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)：固定 question/owner、Status 0、公网 IPv4 后，还须原域名完整 TLS 的 `--resolve` marker 请求为 200 且实际 IP 等于候选，才尝试写 hosts。HTTP、TLS 和产物错误不会进入备用解析；没有第二 DoH 服务、CNAME 扩展或永久 IP。`verification/ci/test_fork_host.py` 的单文件 stdlib check 以 fake curl/sudo 验证边界，真实 hosts 不参与测试。

[连续消费诊断 run 37563968869](https://github.com/gycrosskit/live-sdk/actions/runs/37563968869) 以空同一 Gradle home 先构建 rc.7 Kuikly APK（3m4）再构建 CMP APK（2m26）全部通过，两个 JVM DNS 都成功，未复现第二次 marker 故障。PR #25 首轮发布基线的 Native 第二 JVM 三次预解析全部 UnknownHost；Android 第二 JVM 预解析成功仍 marker 失败，其精确根因仍未确认。
