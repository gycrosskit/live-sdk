## 模块与平台

| 模块 | 内容 | UI 依赖 |
| --- | --- | --- |
| 根 `live-sdk` | 两个子模块的 Gradle 聚合与版本/许可配置，不发布产品 | 无 UI |
| `live-core` | 原有 SDK 账号、会话队列、预览状态机、StateFlow 快照、互动、原生视频 View 与 iOS Bridge | 无 Compose / Kuikly |
| `live-kuikly` | `LiveVideo` / `KuiklyLiveView`、Android `GycLiveView`、iOS Controller 与 Swift 原生 View | Kuikly core/render + KuiklyCompose/runtime；无第二套CMP UI |

Android SDK 仍依赖 `io.trtc.uikit:atomicx-core:4.3.3.29` 与 `com.tencent.imsdk:imsdk-plus:9.1.7818`。iOS 宿主的 `IosLiveSdkBridge` 可将协议映射到原生 Pod `GycLiveNative`；原生 Pod 传递依赖 AtomicXCore/RoomEngine/IM，本组件不会生成 UserSig 或复制业务 Repository。

安装时按 README 将 `com.tencent.kuikly-open` 通过 `exclusiveContent` 路由到 `https://mirrors.tencent.com/nexus/repository/maven-tencent/`，让 Kuikly metadata 与 AAR/KLIB 来自同一已验仓库。该规则只约束 Kuikly group，不排除其他 SDK 或修改插件仓库。

KuiklyCompose入口已通过真实Compose runtime接线测试与公开consumer编译/link；native节点边界注入，尚未验收真实Renderer音画。Kuikly 视频层与原生宿主共用 `live-core`；原生 SDK 账号、全局观看会话队列和快照规则只有一份。完整观看与预览互斥；移除控件和 `release()` 会清理观看会话，等待 SDK 离房回调或既有超时后放行下一会话。


## 账号准备

Android 继续通过 `AtomicXSession` 使用宿主提供的 SDK 账号和 UserSig，成功后调用 `AndroidLiveSdkRuntime.updateSessionReady(true)`。iOS 启动时继续 `IosLiveSdkRuntime.install(existingBridge)`，账号准备成功后 `updateSessionReady(true)`。注销或撤销播放资格前先设为 `false` 并停止预览，然后执行既有账号清理流程。

`sessionReadyFlow` 是只读门禁；视频节点读取它，不自行登录。原生宿主与 Kuikly 读取相同 `LiveAudienceContentSnapshot`，平台 Store 只进入 `live-core`。

## 线程与停止顺序

Android/iOS `stopActivePreview()` 保留 Main 同步入口：返回时当前列表预览已停止、原生 View 已移除；后台调用会立即拒绝。Kuikly Renderer 的协程应调用 `stopActivePreviewAndAwait()`，挂起等待 Main 完成，再继续账号准备、重置或完整进房。不要用阻塞等待把 Renderer 和 Main 相互锁住。common `AtomicLivePreviewRuntime` 的同步入口同样只供 Main 使用；iOS 宿主使用平台 Runtime，以包含 Swift 的幂等清理。

```kotlin
// Android Renderer/后台协程；iOS 使用 IosLiveSdkRuntime 同名方法。
AndroidLiveSdkRuntime.stopActivePreviewAndAwait()
prepareLiveAccount()
```

`updateSessionReady`、`sessionReadyFlow` 只访问线程安全 StateFlow，允许任意线程；它们不会代替停止预览。Android `AtomicXSession.isLoggedInAs` 是 Main 同步 SDK 查询，后台应先 `withContext(Dispatchers.Main.immediate)`。`login`、`logout`、`updateProfile` 在 Main 访问 SDK；后台 `updateProfile` 返回只表示已安排执行，执行时再次校验当前账号，未承诺资料写入完成。iOS 原生账号入口沿用既有 Main 调度。

原生/Kuikly 的 View 创建、命令和释放仍遵循平台 Main 合同。Android SDK 会话/互动事件先切 Main，再校验实例是否释放；入房成功先被状态机接纳才更新房间快照。退出期间迟到成功仍清理真实 SDK 会话，关播、禁言和成员事件不能复活已离开的页面。发送命令完成回调归原发起者，离房后的点赞成功继续携带原房间和原用户上报；宿主负责请求代次与超时。


## Kuikly 接线

```kotlin
LiveVideo {
    attr {
        size(320f, 180f)
        room(liveId, preview = true, active = visible)
    }
    event {
        liveEvent { event ->
            // type: previewState、joinStarted、joinSucceeded、joinFailed、
            // liveUnavailable、kickedOut、liveEnded、messageDisabled、snapshot
        }
    }
}
```

完整观看使用 `preview = false`。业务只能在 `joinSucceeded` 后继续执行需要进房成功的动作；`snapshot` 使用原有快照字段，成员事件 `kind` 保留语义，最终文案由宿主提供。`sendBarrage`、`like`、`toggleFollow`、`refreshAudience`、`release` 通过 Kuikly View 方法转发现有 SDK 命令。配置采用单个 `room` JSON，避免属性顺序导致错误模式的 SDK 会话；旧会话迟到回调不会更新新房间。

`KuiklyLiveView.release()` 只退出当前会话，直到重新设置 `room` 才恢复；可见性或账号状态变化不会自行重启。原生节点销毁才永久释放 iOS controller，两端使用同一退出/重启合同。

KuiklyCompose 使用 `io.github.gycrosskit.livesdk.kuikly.LiveVideo`，由组件管理节点、room 更新去重、旧事件隔离和释放；宿主只组合业务控件。原六参数入口保留。需要挂载前注入时使用带 `likeReporter` 的重载；reporter 随节点冻结，变更业务归属时用 `key` 创建新节点。可选 `roomExtras: Map<String, String>` 仅透传宿主 adapter 的额外字段，不能覆盖 `liveId/preview/active`；App 房间 ID、账号和成功尾批上报仍由宿主捕获。

`event.dispatchLivePlaybackEvent(callbacks, onPlaybackError)` 分派已确认的播放事件，未知事件返回 false；技术播放错误不当作关播。`event.toLiveAudienceSnapshot()` 解码 snapshot 为既有中立模型，非对象字段和数组项会跳过；成员 `kind` 与业务透传数据保持原样，显示文本和业务模型转换留宿主。这些新增入口属于当前源码候选，不能用旧发布版本替代消费验证。

Android 在 Kuikly delegate 的 `registerExternalRenderView` 注册：

```kotlin
kuiklyRenderExport.renderViewExport(KuiklyLiveView.VIEW_NAME, { context ->
    GycLiveView(context).also { it.likeReporter = existingBusinessLikeReporter }
})
```

预览需要宿主的 `ViewTreeLifecycleOwner`，页面至少 STARTED 且 `active=true` 才播放；没有 LifecycleOwner 时保持封面。视频节点不提供操作层，宿主处理触摸、可访问性、语言、主题与业务导航。

Android 的完整 View 树 attach 后启动、最新 room 合并及迟到启动取消由 `GycLiveView` 自身管理；宿主直接注册组件，不再包一层延迟下发 room 的 View。detach 可重挂，显式 release 不自动恢复，onDestroy 永久释放。

iOS 将 [GycLiveView.swift](../live-kuikly/ios/GycLiveView.swift) 加入宿主 target，Framework 模块名为 `LiveKuikly`，链接 `OpenKuiklyIOSRender` 2.28.0。类通过 `@objc(GycLiveView)` 供 Kuikly 动态发现；现有 `IosLiveSdkBridge` 负责真实腾讯 SDK。宿主可在创建节点后设置 `likeReporter`。Swift View 响应页面挂载和 UIApplication 前后台事件，停止列表预览；销毁时幂等释放。静态 KMP Framework 的 native C 符号由最终宿主的真实 Kuikly Render Framework 提供。

Kuikly View 的 `enterPictureInPicture` / `updatePictureInPicture` 复用 core 的既有观看会话和宿主原生能力。完整业务页面、礼物、上麦、开播和服务器协议不由本组件实现。


## iOS Framework 导出

iOS Maven 产物为 KLIB，不是独立 Swift Package。Swift 实现 `IosLiveSdkBridge` 时，应用的 KMP Framework 必须 `export` 与 `api` 同版本 `live-core`；Kuikly 还需导出 `live-kuikly`。参考 [独立消费工程](../verification/consumer/build.gradle.kts) 的静态 Framework 配置。Native C 符号由真实 OpenKuiklyIOSRender Framework 提供，不能以伪造符号或允许未定义符号绕过链接。

Kuikly 的 `GycLiveView.swift` 从已发布 Maven 不可变标签 `0.2.1-rc.13` 取得，包含当前会话 release 与后续 room 重入合同；不从 main 或旧 rc.3 接线替代。它独立于下方 `GycLiveNative` Git Pod rc.13。旧 rc.3 / Maven rc.5 组合与验收属于历史，见 [rc.5 验收记录](0.2.1-rc.5远程发布验收.md)。

## 未发布源码候选：iOS Renderer 出口

本节适用于 2026-10-18 Native-only 发布准备：Pod `0.2.1-rc.15`、Tag `native-0.2.1-rc.15`。公开旧 Tag `0.2.1-rc.13` 不含新增 subspec，不覆盖旧标签；Maven 仍为 `0.2.1-rc.13`。正式使用前核对该 Native Release 与精确远程消费门禁结果。应用的 Core/Renderer 必须使用同一 Git source/tag：

```ruby
native = { :git => 'https://github.com/gycrosskit/live-sdk.git', :tag => 'native-1.0.1' }
pod 'GycLiveNative/Core', **native
pod 'GycLiveNative/Renderer', **native
```

只验证 Renderer 的应用可只声明第二行；它仅依赖 `OpenKuiklyIOSRender 2.29.1`，不会带入 Core/腾讯 SDK、KMP 或 CMP。默认 `pod 'GycLiveNative'` 仍选择 Core。独立 consumer 固定与接入应用一致的 Render `2.29.1` Git tag；最低系统 iOS15。

`GycLiveRendererView` 通过实例 `controllerFactory` 接收 `GycLiveRendererController`。协议只含 `view/configure/setVisible/command/release`，参数为 UIKit 与 Swift 基础类型，隔开不同 KMP Framework 的导出 ABI。Pod 不 import `LiveKuikly` 或 `Shared`，也不持有账号、业务 Repository 或点赞上传实现。

1. Framework 名为 `LiveKuikly` 时，加入候选 [GycLiveView.swift](../live-kuikly/ios/GycLiveView.swift)；该文件只做 controller 类型映射与 `@objc(GycLiveView)` 注册，保留创建会话前设置 `likeReporter` 的入口。
2. Framework 名为 `Shared` 等其他名称时，在应用 target 写同样的薄 adapter，映射**该应用自己导出的** `IosKuiklyLiveController`。不能把另一个 `LiveKuikly.framework` 的 Kotlin 类型强转为 `Shared` 类型，也不能靠仅替换 import 声称已验证 ABI。
3. 应用注册类继承 `GycLiveRendererView`，在 initializer 给实例 `controllerFactory` 赋值；adapter 的 `configure(value:)` 在转交原始 room JSON 前注入房间对应的业务 `likeReporter`。房间 ID 捕获、业务上报与 Shared 映射留在应用，不需要再复制事件缓存、CSS setter、通知 observer 或 release。

应用侧的类型映射主体如下；业务 reporter 的创建仍沿用应用已有端口，不应写入 Pod：

```swift
// 此文件属于应用 target，Shared 是应用自己的 KMP 导出模块。
import UIKit
import Shared
import GycLiveNative

final class AppLiveController: GycLiveRendererController {
    let controller: IosKuiklyLiveController
    init(onEvent: @escaping (String) -> Void) {
        controller = IosKuiklyLiveController(onEvent: onEvent)
    }
    var view: UIView { controller.view }
    func configure(value: String) {
        // 应用在此用自己的房间映射设置 controller.likeReporter，然后转交。
        controller.configure(value: value)
    }
    func setVisible(value: Bool) { controller.setVisible(value: value) }
    func command(method: String, params: String, callback: @escaping (String) -> Void) {
        controller.command(method: method, params: params, callback: callback)
    }
    func release() { controller.release() }
}

// 注册类 initializer 中：
// controllerFactory = { AppLiveController(onEvent: $0) }
```

调用均在 Main。首次有效 room 前安装 factory；未安装时回 `joinFailed` / code=-1，不伪造会话成功。基类负责 Objective-C `setCss_liveEvent:` Block 桥接、16条事件缓存、窗口/应用可见性、owner 撤销和幂等释放；factory 返回期间若节点已被移除，返回的 controller 立即释放。换房与移除不把旧缓存回放到后继节点。`release` 页面命令仍交 Kotlin controller 停当前会话；节点移除才销毁 controller。当前候选的 Renderer-only 真 Pod/六项 Swift Simulator 回归与 iphoneos Framework 构建已通过；旧 LiveKuikly Kotlin 导出链接与应用 Shared 薄桥仍未验证，不替代应用业务、云账号或设备验收。

### 原生使用

```swift
import GycLiveNative
import UIKit

struct PreviewObserver: GycLivePreviewObserver {
    func onLoading() {}
    func onPlaying() {}
    func onFailed(code: Int32, message: String) {}
}

// 宿主完成账号准备与播放准入后使用；预览保持静音，不调用 joinLive/leaveLive。
let client = GycLiveClient.shared
let preview = client.makePreviewView(liveId: validatedLiveID, observer: PreviewObserver())
container.addSubview(preview)
// 宿主根据容器尺寸布局；失活或销毁时成对释放。
client.releasePreviewView(view: preview)
```

`GycLiveClient.shared` 持有进程内唯一账号/视频会话，所有 SDK 访问与回调切到主线程：

| API | 回执与边界 |
| --- | --- |
| `isLoggedInAs`、`currentUserId` | 查询实际 AtomicX 登录状态；未登录用户 ID 为空 |
| `login`、`updateProfile`、`logout` | 只消费宿主身份和 UserSig；换账号先注销旧账号，空昵称回退 userId |
| `makePreviewView`、`releasePreviewView`、`stopPreview` | 唯一静音预览，释放旧 View 不会误停新预览 |
| `makeAudienceView`、`releaseAudienceView` | 进房成功才绑定互动 Store；释放完成回调反映真实 `leaveLive` 结果 |
| `sendBarrage`、`sendLike`、`refreshAudience` | 发送原始文本/合并后的计数，业务表情编码与合并规则由宿主处理 |
| `checkFollowed`、`updateFollow`、`fetchFans` | 仅转换腾讯单用户结果，业务请求代次由上层状态机维护 |
| `connectLiveIm`、`disconnectLiveIm` | 接收宿主已校验群组白名单，过滤 UTF-8 原始消息与当前用户被踢；不解析业务 payload |
| `enterPictureInPicture` | 返回值仅表示 RoomEngine 请求已提交，观察者获得异步响应 |
| `enableBackgroundPictureInPicture`、`disableBackgroundPictureInPicture` | 后台准备单独回执，不改变宿主前台小窗状态 |
| `setLogger` | 可选日志出口；默认不写系统日志，不记录凭据或消息正文 |

`GycLiveOperationCallback` / `GycLiveBooleanCallback` / `GycLiveLongCallback` 与播放/预览/IM 观察者公开签名仅使用 Swift 标量、数组和 UIKit `UIView`，无腾讯类型。账号回执必须在调用方串行门禁内消费。注销会发起观看离房与 IM 撤销，再注销账号；logout 回执是账号回执，不能冒充观看 leave 回执。纯 UIKit 消费者同样应等待 `releaseAudienceView` 回执后再创建下一观看 View；KMP 共用队列继续留在 `live-core`。

### KMP 薄桥与生命周期

宿主仅实现 `IosLiveSdkBridge` 并创建小型 callback/observer 映射，保留现有 `IosLiveSdkRuntime.install(bridge)`。不要把 Shared Framework 名硬编码到原生 Pod。原生不持有业务 Coordinator、UserSig 获取、品牌准入、错误 UI 或导航。组件会使失效 View、互动订阅、完整观看事件与 IM Listener 失去回调资格；同一 liveId 重连也校验实例代次。发送命令的完成回调仍交给发起者，以保留离房后点赞成功上报的原房间语义；上层继续负责请求代次与超时。

系统 PiP 继续使用 RoomEngine `enablePictureInPicture` 实验 JSON 的 `room_id`，标准视频 `9:16`，宽内容 `16:9`。不创建第二播放器，不重绑渲染或重复进房。前台应用内小窗、拖动贴边、宿主控制器父容器与系统前后台呈现状态仍由宿主维护；从系统 PiP 回前台小窗时不能调用 disable，恢复全屏或关闭直播才关闭系统 PiP。实验接口响应不能证明系统浮窗已可见，SDK 升级必须真机回归。

## Kuikly PiP 命令

当前源码新增 `KuiklyLiveView.enterPictureInPicture(wideContent, callback)` 和 `updatePictureInPicture(enabled)`，Android/iOS Native View 均复用已有观看会话。`callback` 的 `accepted` 仅表示 Android 系统接受请求或 iOS 实验接口请求已提交。未就绪、预览、已释放或布尔参数格式不正确时回执为 false，不修改浮窗状态。

Android 宿主在 Activity 的 `onPictureInPictureModeChanged` 将真实值交给 `updatePictureInPicture`；请求阶段快照读取 `Activity.isInPictureInPictureMode`。iOS 原厂实验接口仍只提供 SDK回执，不能将 `accepted` 当浮窗可见性；宿主有真实平台生命周期回报时才同步该状态。现有 snapshot/event 继续共享 core 的唯一状态，设备浮窗、画面声音及恢复退出需要真实验收。该 API 自 `0.2.1-rc.7` 提供，旧 `0.2.1-rc.6` 不能消费此 API。
