# Live SDK 接入指南

版本和远程坐标见 [README](../README.md)。本文描述接入应用需要完成的 SDK 账号、原生注册和生命周期接线。

## 模块与平台

| 模块 | 内容 | UI 依赖 |
| --- | --- | --- |
| 根 `live-sdk` | 原 CMP `LivePreview` / `LiveCoreView` / `LivePlaybackState` | CMP runtime/ui |
| `live-core` | 原有 SDK 账号、会话队列、预览状态机、StateFlow 快照、互动、原生视频 View 与 iOS Bridge | 无 Compose / Kuikly |
| `live-kuikly` | `LiveVideo` / `KuiklyLiveView`、Android `GycLiveView`、iOS Controller 与 Swift 原生 View | Kuikly core/render，**Native DSL** |

Android SDK 仍依赖 `io.trtc.uikit:atomicx-core:4.3.3.29` 与 `com.tencent.imsdk:imsdk-plus:9.1.7818`。iOS 宿主的 `IosLiveSdkBridge` 可将协议映射到新原生候选 `GycLiveNative`；原生 Pod 传递依赖 AtomicXCore/RoomEngine/IM，本组件不会生成 UserSig或复制业务 Repository。

Kuikly Compose DSL 不在当前验证范围。Kuikly 视频层与 CMP 可在同一应用内共用 `live-core`；原生 SDK 账号、全局观看会话队列和快照规则只有一份。完整观看与预览互斥；移除控件和 `release()` 会清理观看会话，等待 SDK 离房回调或既有超时后放行下一会话。


## 账号准备

Android 继续通过 `AtomicXSession` 使用宿主提供的 SDK 账号和 UserSig，成功后调用 `AndroidLiveSdkRuntime.updateSessionReady(true)`。iOS 启动时继续 `IosLiveSdkRuntime.install(existingBridge)`，账号准备成功后 `updateSessionReady(true)`。注销或撤销播放资格前先设为 `false` 并停止预览，然后执行既有账号清理流程。

`sessionReadyFlow` 是只读门禁；视频节点读取它，不自行登录。Native 与 CMP 读取相同 `LiveAudienceContentSnapshot`，平台 Store 只进入 `live-core`。


## Kuikly 接线

```kotlin
LiveVideo {
    attr {
        size(320f, 180f)
        room(liveId, preview = true, active = visible)
    }
    event {
        liveEvent { event ->
            // type: previewState、joinStarted、joinSucceeded、joinFailed、
            // liveUnavailable、kickedOut、liveEnded、messageDisabled、snapshot
        }
    }
}
```

完整观看使用 `preview = false`。业务只能在 `joinSucceeded` 后继续执行需要进房成功的动作；`snapshot` 使用原有快照字段，成员事件 `kind` 保留语义，最终文案由宿主提供。`sendBarrage`、`like`、`toggleFollow`、`refreshAudience`、`release` 通过 Kuikly View 方法转发现有 SDK 命令。配置采用单个 `room` JSON，避免属性顺序导致错误模式的 SDK 会话；旧会话迟到回调不会更新新房间。

Android 在 Kuikly delegate 的 `registerExternalRenderView` 注册：

```kotlin
kuiklyRenderExport.renderViewExport(KuiklyLiveView.VIEW_NAME, { context ->
    GycLiveView(context).also { it.likeReporter = existingBusinessLikeReporter }
})
```

预览需要宿主的 `ViewTreeLifecycleOwner`，页面至少 STARTED 且 `active=true` 才播放；没有 LifecycleOwner 时保持封面。视频节点不提供操作层，宿主处理触摸、可访问性、语言、主题与业务导航。

iOS 将 [GycLiveView.swift](../live-kuikly/ios/GycLiveView.swift) 加入宿主 target，Framework 模块名为 `LiveKuikly`，链接 `OpenKuiklyIOSRender` 2.28.0。类通过 `@objc(GycLiveView)` 供 Kuikly 动态发现；现有 `IosLiveSdkBridge` 负责真实腾讯 SDK。宿主可在创建节点后设置 `likeReporter`。Swift View 响应页面挂载和 UIApplication 前后台事件，停止列表预览；销毁时幂等释放。静态 KMP Framework 的 native C 符号由最终宿主的真实 Kuikly Render Framework 提供。

PiP 仍通过原 CMP/宿主既有原生能力使用；本轮 Kuikly View 未新增 PiP 指令。完整业务页面、礼物、上麦、开播和服务器协议不由本组件实现。


## iOS Framework 导出

iOS Maven 产物为 KLIB，不是独立 Swift Package。Swift 实现 `IosLiveSdkBridge` 时，应用的 KMP Framework 必须 `export` 与 `api` 同版本 `live-core`；Kuikly 还需导出 `live-kuikly`。参考 [独立消费工程](../verification/consumer/build.gradle.kts) 的静态 Framework 配置。Native C 符号由真实 OpenKuiklyIOSRender Framework 提供，不能以伪造符号或允许未定义符号绕过链接。

`GycLiveView.swift` 应从与 Maven 相同的不可变 Git 标签取得；请使用 [0.2.0-rc.2 源码](https://github.com/gycrosskit/live-sdk/blob/0.2.0-rc.2/live-kuikly/ios/GycLiveView.swift)，不要混用 main 中未来版本。

## iOS 原生 CocoaPod

`GycLiveNative` `0.2.1-rc.1` 是本地候选，尚未发布 Git tag 或 CocoaPods Specs。Maven 继续使用已发布的 `0.2.0-rc.2`；两种产物分别验证，KLIB 不包含 Swift SDK 实现。Pod 只编译 [ios/Sources/GycLiveNative](../ios/Sources/GycLiveNative)，不依赖 Shared、CMP 或 Kuikly，也不分发腾讯二进制。

```ruby
platform :ios, '15.0'
use_frameworks! :linkage => :static
pod 'GycLiveNative', :path => '/path/to/live-sdk'
```

精确腾讯版本由 [podspec](../GycLiveNative.podspec) 声明。宿主和客服如直接依赖 IM，必须使用相同版本；生产许可、SDKAppId 和服务端 UserSig 由接入方提供。

### 原生使用

```swift
import GycLiveNative
import UIKit

struct PreviewObserver: GycLivePreviewObserver {
    func onLoading() {}
    func onPlaying() {}
    func onFailed(code: Int32, message: String) {}
}

// 宿主完成账号准备与播放准入后使用；预览保持静音，不调用 joinLive/leaveLive。
let client = GycLiveClient.shared
let preview = client.makePreviewView(liveId: validatedLiveID, observer: PreviewObserver())
container.addSubview(preview)
// 宿主根据容器尺寸布局；失活或销毁时成对释放。
client.releasePreviewView(view: preview)
```

`GycLiveClient.shared` 持有进程内唯一账号/视频会话，所有 SDK 访问与回调切到主线程：

| API | 回执与边界 |
| --- | --- |
| `isLoggedInAs`、`currentUserId` | 查询实际 AtomicX 登录状态；未登录用户 ID 为空 |
| `login`、`updateProfile`、`logout` | 只消费宿主身份和 UserSig；换账号先注销旧账号，空昵称回退 userId |
| `makePreviewView`、`releasePreviewView`、`stopPreview` | 唯一静音预览，释放旧 View 不会误停新预览 |
| `makeAudienceView`、`releaseAudienceView` | 进房成功才绑定互动 Store；释放完成回调反映真实 `leaveLive` 结果 |
| `sendBarrage`、`sendLike`、`refreshAudience` | 发送原始文本/合并后的计数，业务表情编码与合并规则由宿主处理 |
| `checkFollowed`、`updateFollow`、`fetchFans` | 仅转换腾讯单用户结果，业务请求代次由上层状态机维护 |
| `connectLiveIm`、`disconnectLiveIm` | 接收宿主已校验群组白名单，过滤 UTF-8 原始消息与当前用户被踢；不解析业务 payload |
| `enterPictureInPicture` | 返回值仅表示 RoomEngine 请求已提交，观察者获得异步响应 |
| `enableBackgroundPictureInPicture`、`disableBackgroundPictureInPicture` | 后台准备单独回执，不改变宿主前台小窗状态 |
| `setLogger` | 可选日志出口；默认不写系统日志，不记录凭据或消息正文 |

`GycLiveOperationCallback` / `GycLiveBooleanCallback` / `GycLiveLongCallback` 与播放/预览/IM 观察者公开签名仅使用 Swift 标量、数组和 UIKit `UIView`，无腾讯类型。账号回执必须在调用方串行门禁内消费。注销会发起观看离房与 IM 撤销，再注销账号；logout 回执是账号回执，不能冒充观看 leave 回执。纯 UIKit 消费者同样应等待 `releaseAudienceView` 回执后再创建下一观看 View；KMP 共用队列继续留在 `live-core`。

### KMP 薄桥与生命周期

宿主仅实现 `IosLiveSdkBridge` 并创建小型 callback/observer 映射，保留现有 `IosLiveSdkRuntime.install(bridge)`。不要把 Shared Framework 名硬编码到原生 Pod。原生不持有业务 Coordinator、UserSig 获取、品牌准入、错误 UI 或导航。组件会使失效 View、互动订阅、完整观看事件与 IM Listener 失去回调资格；同一 liveId 重连也校验实例代次。发送命令的完成回调仍交给发起者，以保留离房后点赞成功上报的原房间语义；上层继续负责请求代次与超时。

系统 PiP 继续使用 RoomEngine `enablePictureInPicture` 实验 JSON 的 `room_id`，标准视频 `9:16`，宽内容 `16:9`。不创建第二播放器，不重绑渲染或重复进房。前台应用内小窗、拖动贴边、Compose 控制器父容器与系统前后台呈现状态仍由宿主维护；从系统 PiP 回前台小窗时不能调用 disable，恢复全屏或关闭直播才关闭系统 PiP。实验接口响应不能证明系统浮窗已可见，SDK 升级必须真机回归。
